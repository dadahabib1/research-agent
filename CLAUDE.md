# research-agent (plugin repository)

This repository is a Claude Code plugin marketplace with one plugin, `research-agent`, in `plugins/research-agent/`. The plugin is a tool a project installs; it writes only into that project's repository, never into this one.

- Skills live in `plugins/research-agent/skills/`; agents in `plugins/research-agent/agents/`; the doctor in `tools/`; the consumer kit in `kit/`.
- Keep the research protocol general. Domain rules belong to the consuming project, written from `skills/new-research-project/templates/domain-rules.md` and pointed to by its brief §6; the plugin holds only general rules, and the files a run reads carry no field's examples.
- `plugins/research-agent/CONTRACT.md` lists what hosts depend on. Before 1.0, a minor release may change it and a patch never does; each release records its changes under "Contract" in `CHANGELOG.md`, and a removal is deprecated for one minor release first.
- **Versions change only at release.** A pull request adds a line under `## Unreleased` in `plugins/research-agent/CHANGELOG.md` and leaves `version` alone. A release pull request moves Unreleased under `## X.Y.Z (date)`, sets `version` in `plugins/research-agent/.claude-plugin/plugin.json` (and the matching `__version__` label in `servers/fetch_raw/fetchraw/__init__.py`, which the fetcher's test checks), updates `UPGRADING.md`, and restamps the kit with `python plugins/research-agent/tools/stamp_kit.py`. After the merge, the owner tags the merge commit `vX.Y.Z` and publishes the section as the release notes. A tag is never moved; a fix is a new patch release.
- Test with `uv run --script plugins/research-agent/tools/tests/run.py`, `uv run --script plugins/research-agent/kit/tests/run.py`, the fetcher's `servers/fetch_raw/tests/run.py`, `claude plugin validate ./plugins/research-agent` and `claude --plugin-dir ./plugins/research-agent` before pushing. After merging, refresh this machine's copy with `claude plugin marketplace update personal-agents`, then `/reload-plugins` in open sessions. The plugin is a relative-path plugin enabled through project settings, so it has no install record and `claude plugin update` does not apply.
- Lessons: runs list `[tool]` lesson candidates in their hand-back, and hosts file them as issues labelled `lesson` here. At each sprint review the owner sorts open lessons into the next release or closes them; a release adds accepted ones to `skills/research-protocol/references/takeaways.md`, each with its incident and check, after checking that no existing entry already covers the rule.
